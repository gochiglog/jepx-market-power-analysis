# データを読むときの疑問

全体の入口は [README](../README.md)、実物は [日本語閲覧ノートブック05](../notebooks/05_data_browser_ja.ipynb)です。

## 「案A」は原本なのか

違います。案Aは「発電実績に、取得版に収録された公表停止記録を別列で併記する」という診断データの作り方です。
元の参照容量差は変更せず、停止量を差し引いていません。実際に停止していたと認定した表でもありません。

[原本取得一覧](../reports/issue_4_closeout.md)は公式ファイルの一覧です。一方、以前の閲覧ノートブックは原本・基本表・案Aの派生表を見分けにくい形で並べていました。
新しい画面では「基本台帳」と「比較・診断」を分け、案Aの市場表は「停止公表記録付き市場表」と表示します。原本や固定版の名前・中身は変えません。

## 7,828と58,852は何の数か

**取得した元停止CSVの行数**です。市場表の行数でも、異なる停止イベントの確定件数でもありません。

| 取得版 | 分かっている取得条件 | 比較用の市場表 |
|---|---|---:|
| 7,828行 | ユーザーがFY2025を指定して手動取得。取得時刻は不明 | 157,680行 |
| 58,852行 | 期間条件なしで自動取得。2026-10-08 17:27:11 JST | 157,680行 |

同内容のコピーや更新候補が含まれます。単純に大きい方が正しい、全行が独立イベント、手動版が完全な部分集合、と判断していません。
同じ発電実績に照合する公表記録が違うため、主区分は全国57,186セルで変わりました。発電量や容量そのものを変えた差ではなく、**公表記録の区分への振り分けの差**です。
両取得版を混ぜず、比較条件として保持します。どちらを最終baselineにするかは未確定です。

## 早端・遅端は何が違うか

公表の復旧予定には日付だけで、日内の時刻がありません。例えば復旧予定日が6月10日なら、次を比較します。

| 表示 | 仮の予定区間の終わり | 6月10日の扱い |
|---|---|---|
| 早端／予定日の始めまで | 6月10日00:00 | その日のコマは区間外 |
| 遅端／予定日の終わりまで | 6月11日00:00 | その日のコマまで区間内 |

これは診断シナリオであり、元の日付を実際の復旧時刻に置き換えたものではありません。
主区分は復旧予定日を境界不明として保留する設計なので、早端・遅端で主区分差が0になります。
しかし、予定区間該当フラグは58,852版で154,581セル、7,828版で154,464セル異なります。「端点の仮定が影響しない」という意味ではありません。
停止記録がない場合も、停止なし・利用可能とは判断しません。

## なぜ列名に日本語・英語が混在し、数値がstringになっていたのか

公式CSVの日本語列を**元文字列のまま保存**し、そこへ日付・数値へ変換した英語列を追加したためです。例えば元の「空容量」と、数値型の `available_capacity_mw` は役割が違います。
原列は追跡用に必要ですが、すべてを普段の画面に並べると読みにくくなります。

今回の閲覧層では英語標準名を統一し、画面は日本語名＋単位にしました。通常は主要な数値列を表示し、原列は「詳細・監査」で確認します。
[全列対応表](../metadata/view_column_dictionary.csv)には英語標準名、日本語名、単位、実際の型、元列名、定義を記録しています。
これは新しい読み取り用ビューです。既存固定ファイルの列・型・原値は変更していません。

## 実績のシステムプライスはどれを見るのか

普段は **spot市場CSV由来の `system_price_market`** を見ます。既存spotファイルの `system_price` と同じ採用系列です。
感応度側の基準価格は詳細・監査へ保存します。仮想価格と公表差分を解釈する際に必要なので、spot価格で上書きしません。
既知QAは監査・RD-008に残し、通常の閲覧画面で繰り返し警告しません。

## この連系線の1行は何を示すのか

質問にあった行は「**2025年4月1日00:00–00:30の、北海道→東北方向について、翌々日断面で策定された系統情報**」です。

| 値 | 意味 |
|---|---|
| 2025-04-01 | 電力の受渡日 |
| period 1 | 日本時間00:00–00:30 |
| 北海道・本州間電力連系設備 | 対象設備名 |
| 順方向 | この設備では北海道→東北と公式資料で方向を確認 |
| `["北海道"]` | 送出側の地域集合。ここでは北海道1地域 |
| `["東北"]` | 受入側の地域集合。ここでは東北1地域 |
| 680.000000 | 公表空容量680 MW |
| 700.000000 | 公表運用容量700 MW |
| 0.000000 | 公表計画潮流0 MW。実潮流が0だったという意味ではない |
| `official_orientation_verified` | 方向を公式資料で確認済みという処理上の状態 |

同じ行にはマージン20 MWもあります。最後の英語は新しい数量ではありません。
この値は翌々日策定時の公表値で、その時間に実際に680 MWを追加輸入できたと確定するものではありません。質問の行は北海道への輸入ではなく、北海道からの送出方向です。
逆方向は別行です。元の符号を保持しており、一律の絶対値化・合算はしません。
