# ユニット情報を保持する二層データ設計

RD-010（2026-10-16ユーザー承認）に基づき、元unit情報を保持し、必要に応じplantへ集約できる構造とします。
「可逆的」は集約元データと対応履歴を保持して再集計できる意味です。合計値だけからunit値を復元する意味ではありません。
分析baselineをunit/plantのどちらにするか、headroomとoutageの適用粒度は未確定です。

| 層 | 保持する情報 | 現時点の扱い |
|---|---|---|
| 元unit観測 | 元code・area・plant/unit名称・30分kWh・元行・出典SHA・時間キー | 既存longを保持。欠測や未対応を削除しない |
| 設備対応候補 | source識別子・target識別子・設備階層候補・確認レベル・根拠・有効期間の確認状態 | strictと追加候補を別管理。自動採用はしない |
| plant集約候補 | 集約に使用するunitの集合、各対応の根拠と版、対象期間、元データへの参照 | 今回は未実装。研究判断後に仕様化する |

原sourceのplantラベルは物理サイトとは限りません。同一コードの系列・軸を独立unitとして残します。
HJKSのブロックと構成GT/STを重ねて加算せず、旧設備と更新設備も区別します。
コード対応、capacityの期間、outageの復旧・更新ルール、法人帰属はそれぞれ独立して審査します。

正式対応と感度確認の候補は混在させず、集約を実装する際には入力unit集合と未一致・曖昧件数を出力します。
今回の公式調査は [上位10コード報告](../reports/top10_official_asset_review_20261016.md) を参照してください。
