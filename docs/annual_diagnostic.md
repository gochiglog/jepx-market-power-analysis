# FY2025・固定供給を残す年間代替供給診断の入力契約

4月は方法検証、研究対象はFY2025。実績D、固定するPV/風力/原子力実績R、N=D−R、名参照による調整供給のみの全地域除去、保存留保枠B、既存17条件を維持する。正式mapping・所有/支配/契約への昇格はしない。室蘭100MW・釧路112MWの参照値は卸/発電端/送電端が統一済みではない。算定式とstatusは[既存数式仕様](central_spec_audit.md)に従う。

## 原本とETL

- 4月8地域の一次CSVと中部年度ZIPを再利用し、未保有88地域月だけを公式元から取得。再開時は取得manifestのSHA一致を条件に既存取得分を再利用する。
- 中部年度ZIP内の12CSVと他8地域12か月、108地域月。全元列・元文字列・全空欄paddingをファイル別表に保持する。
- 入力はMW平均、30分。九州は原時刻を区間終端、他8地域は開始として既存契約を継承。中部の以前のkWh月次系統値ではなく、保有年度ZIPのMW燃料別値を使用する。
- 関西2026年3月にCR単独改行があり、`StringIO(newline="")`で厳密に読み分ける。原バイトは変更しない。列構成/単位/改行/時刻を地域月契約として保存。
- Rは制御後の実績として公表されたPV/風力と原子力の和。制御量を加えず、自家消費を再控除しない。純揚水/蓄電は原符号を保持するが、総充電を推定生成しない。公表需要を満たし、観測充電の再現を求めない既存会計を維持する。
- REIは統合CSVの明示地域ヘッダーを検算用に参照する。保存名とヘッダーが異なる地域別8ファイルを名前だけで採用しない。一次値をREIへ置換/修正しない。

## 年間上限

9つの既存年間unit供給表（控除なし＋停止8）を再利用し、記録保留に追加控除なし8条件を派生して17条件とする。原子力32ラベルを調整側から外し、既存9地域372候補＋外部非重複確認2候補＝374ラベルを候補にする。原unit観測のない日を追加しない。各条件は元8,468,544行と元列・宣言型を保持。数値が定義できる部分和と、保留設備数/既知参照容量/容量不明を別に残す。参照上限から実績発電を再控除しない。

元kWのsumはDecimalで保持し、MWへの変換は `/1000` を明記する。Arrowの除算中間precisionが38を超えないよう、値域を検査するsafe cast `decimal128(28,6)` を用い、派生MWは小数9桁で保存する。元の容量/上限列はcastしない。

## 送電切替：旧残存表示を別能力へ足さない

保存公式 [切替通知](https://www.occto.or.jp/assets/institution/keitoujouhou/202602keitou_jyouhou_nakachiiki.pdf) 物理2/5と [第114回資料2](https://www.occto.or.jp/assets/chousei_114_02.pdf) 物理7/8を根拠に、中央3地域の個別上限からフェンス管理へ分ける。

- 2025/4/1〜2026/3/12：既存10区間＋北陸フェンスの11制約、16,608コマを値・係数・元行で旧固定版と照合。
- 3/13以降：対象コマに新3フェンスの順逆公表行が揃う場合だけ、新3フェンス＋中央以外7区間の10制約を適用。三重/南福光/越前の残存元行は別表へ保持するが、独立上限として重ねない。
- 3/14〜3/31の864コマは新3フェンスが揃う。3/13の48コマは不足しており送電ありを保留。予定のリリース完了時刻を補って新/旧へ割り当てない。
- 10本の補助輸送変数の接続は維持。M=三重、S=南福光、E=越前とすると、中部M＋S、北陸S−E、関西M＋E。3係数は `F中部−F関西=F北陸` で従属し、3本の独立追加容量ではない。
- 切替後の中央3辺は地域間純移送を表す補助変数であり、個別物理線の能力/実潮流と解釈しない。内部循環を加えても3地域の純受送電とフェンス量は変わらない。中央の純移送は3カットが規定し、旧辺の残存表示値を使わない。予定ルート断を実施確定として容量0を追加する操作も行わない。

これは公表フェンスの保存包絡を用いる**地域輸送モデル**の通常実装で、実系統切替の完了時刻・潮流法則・個別線の運用再現を証明したものではない。全年度17,520コマと、制約入力の揃う17,472コマを区別する。包絡なし比較は同じ9地域接続のまま全17,520コマで計算可能だが、あり/なしの対比較は共通入力/時刻で行う。

## 計算・高速化・再開

固定元Nの全法人同時成立→企業除去後同時成立→正の対象Nの地域倍率→同一入力の送電比較の順に行う。全法人不成立、他地域固定の倍率問題不成立、純需要非正、入力不足/送電保留、数値失敗を分離する。同時成立は最大倍率から推測しない。

既存のg9・f10を保ち、地域倍率では `q=lambda N_target` を変数として最大化し、最後に正のNで除す。対象行の係数を固定でき、正のNでは元式と等価。過不足変数を本計算へ入れない。HiGHSモデルの行/列上下限を更新して再利用し、全解の会計/制約/変数上下限残差を検査する。[公式Python例](https://github.com/ERGO-Code/HiGHS/blob/master/examples/Docs.py)のモデル受渡しAPIを使用。依存版はuv.lockに固定する。

完全に同じN/U/送電包絡/対象地域の入力だけキャッシュする。sourceの保留件数等は別列に保持し、数値同値だから元情報を削除しない。上限除去で全法人不成立が成立へ改善しないこと、無制約で `0<=sumN<=sumU` の解析式、qの解析上端を検算する。数値表の対象枠数と実ソルバー呼出し数を分ける。

月別の結果・数値標本・checkpointを保存する。checkpointのある月は再計算せず、原資料/入力/結果SHAで版を固定する。途中版は採用版と区別し、既存固定版を上書きしない。
